## 仕様

### 投稿時の入力内容

| 項目 | 必須 | 補足 |
| --- | --- | --- |
| 写真 | 必須 | 1枚以上10枚以下 |
| 題名 | 必須 | |
| ファッションの種類 | 必須 | 別のページに移動して、あらかじめ登録してあるファッションの種類を選択する。1投稿につき1つ |
| タグ | 必須 | 別のページに移動して選択する点は同じ。違うところは手入力で設定できるところがある点 |
| 着用アイテム | 任意 | 自由記述のテキスト（複数行可） |
| 投稿説明 | 必須 | |
| 参考情報 | 任意 | どこのサイトで売っているかを乗せることができる。URLを1つ設定する |

### 文字数の上限（暫定）

チームで正式な値を決めるまでの**暫定値**。決まったら更新する。

| 項目 | 上限（暫定） |
| --- | --- |
| 題名 | 100文字 |
| 着用アイテム | 1000文字 |
| 投稿説明 | 2000文字 |
| 参考情報のURL | 2048文字 |
| タグの数 | 1投稿につき10個まで |
| タグの文字数 | 1つあたり30文字以内 |

### 投稿の流れ（暫定）

投稿した内容を見る画面（投稿の詳細・プロフィールの投稿一覧）ができるまでの**暫定**の流れ。

```
入力画面 ──「確認」──▶ 確認画面 ──「投稿する」──▶ 完了画面
```

| 画面 | 画像 | ボタン |
| --- | --- | --- |
| 入力画面 | `design/Post Creation Screen.png` | 「確認」：入力チェックを行い、問題がなければ確認画面へ |
| 確認画面 | `design/Check post content.png` | 「戻る」：入力内容を保ったまま入力画面へ／「投稿する」：投稿を登録する |
| 完了画面（暫定） | なし | 「続けて投稿する」：空の入力画面へ／「ホームへ」：ホーム画面へ |

- 画面画像の「下書き保存」は、下書きの仕様が未確定のため置かない（確認画面では代わりに「戻る」を置く）
- 完了画面には、投稿した内容の要約（1枚目の写真・題名・ファッションの種類・タグ・写真の枚数）を表示する
- 投稿に失敗した場合
  - 入力内容の誤り・写真のサイズ超過：入力画面に戻し、上部と該当する欄に警告文を出す
  - 接続できない・サーバーのエラー：直す項目がないため、確認画面のまま上部に警告文を出し、もう一度「投稿する」を押せるようにする

> **暫定の理由**：投稿した内容を見る画面がまだないため。投稿の詳細画面ができたら、完了画面の代わりに、投稿した投稿の詳細画面へ移動する形にする。

### ファッションの種類とタグの違い

- **ファッションの種類** … あらかじめ登録してある選択肢からのみ選ぶ
- **タグ** … あらかじめ登録してある選択肢から選べるほか、手入力でも設定できる

### ファッションの種類・タグの管理

- ファッションの種類はDBのマスタテーブルで管理し、後から追加できるようにする
  - 初期データ：きれいめ / カジュアル / モード / ストリート
- タグも1つのテーブルで管理する
  - 運営が登録した公式タグと、ユーザーが手入力したタグを `official` フラグで区別する
  - 選択肢として表示するのは公式タグ
- 使わなくなった選択肢は削除せず非表示にする（過去の投稿が壊れないようにするため）

### 写真のメタデータ（位置情報など）の削除

スマホの写真には撮影場所などが埋め込まれているため、保存する前に取り除く。
投稿の写真・プロフィール画像・DM の画像のすべてで同じ処理を通す（`ImageUploadService` → `ImageMetadataStripper`）。

- 画像をピクセルに展開し、メタデータを付けずに新しいファイルとして保存し直す。元のファイルの付加情報は引き継がない
  - 消えるもの：EXIF（位置情報（GPS）・撮影日時・端末のメーカーと機種・撮影設定）、XMP・IPTC、埋め込みのサムネイル、コメント、
    ファイルの後ろに付いた追加データ（スマホの深度マップなど）
  - 残すもの：色の情報（ICC プロファイル）。広い色域で撮った写真の色を正しく出すために必要で、位置情報や撮影日時は含まない
- 写真の向き（EXIF の Orientation）は、消す前にその値どおりにピクセル自体を回転・反転する（スマホの縦写真が横向きにならないように）
  - 8通りの向きすべてに対応する。画素を並べ替えるだけのため、画質は落ちない
- 画質
  - JPEG は品質 0.95 で保存し直す（保存し直す前後の色の差は平均で 1/255 未満）。ファイルサイズは元より少し増えることがある
  - PNG は可逆圧縮のため、画素は1つも変わらない
- 処理に失敗した場合
  - 向きの情報が壊れていて読めない：そのままの向きとして扱い、メタデータは消して保存を続ける（写真が横向きになることはあっても、情報は残らない）
  - 色の情報（ICC プロファイル）を読めない・付けられない：付けずに保存を続ける（色が少しずれることはあっても、情報は残らない）
  - 展開・回転・書き出しに失敗：**元の画像は保存せずに 400 で断る**（「画像を処理できませんでした。別の画像を選択してください。」）。
    メタデータが付いたまま公開されることを防ぐため。投稿は全部の写真の処理が通ってから保存するため、1枚も保存されない
- この処理を入れる前に保存した画像は対象外（処理し直す場合は別途対応が必要）

## 未確定・要確認

- 各項目の必須／任意
  - 仕様に「任意」と明記されているのは「着用アイテム」「参考情報」のみ。他は必須という理解で合っているか
- タグの上限件数、1タグあたりの文字数上限（現在は暫定値。上記「文字数の上限（暫定）」参照）
- 題名・着用アイテム・投稿説明・参考情報のURLの文字数上限（現在は暫定値。上記「文字数の上限（暫定）」参照）
- 投稿の編集・削除
  - 自分のプロフィールから「編集画面に遷移できる」と記載あり（`profile.md`）
  - 編集できる項目、削除の有無
- 写真の保存先と上限サイズ
  - `CLAUDE.md` のルールにより、画像はDBに保存せずURLのみ保持する
  - 開発中はローカル保存、本番はクラウドストレージを想定
- 写真の色の情報（ICC プロファイル）を残していること（上記「写真のメタデータ（位置情報など）の削除」参照）
  - 残す判断をした。この機能の目的は位置情報の流出を防ぐことで、ICC プロファイルは位置情報ではないため。
    また、消すと服の色が正しく見えなくなり、ファッションアプリとしてはその方が問題になるため
  - ただし、まれにプロファイルを作った機器のメーカー名などが含まれる可能性がある（通常は「Display P3」などの標準のもの）
  - 将来より厳しくする場合は、ICC プロファイルも消す選択がある（その代わり、広い色域で撮った写真の色が少しくすむ）
- 投稿を削除したときに、保存済みの画像をどう扱うか
- 下書き保存の有無
- 投稿の公開範囲（全体公開のみか）
- パネルや確認画面を開いた状態でブラウザの「戻る」を押したときの挙動
  - 現在は、パネル（ファッション選択・タグ選択など）を開いていても、投稿作成画面ごと前の画面に戻る
- `GET /api/posts/me` は、プロフィール画面が `/api/users/{id}/posts` を使うようになったら削除できる
