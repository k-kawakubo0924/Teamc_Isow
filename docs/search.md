## 仕様

- 検索記入欄
- 検索項目選択
  - ジャンル
  - 年代
    - ユーザーの年齢層を指す（ファッションの年代ではない）
    - 区分はプロフィールの年代と同じ（`profile.md` 参照）
  - ユーザ
- 検索項目が選択されたら、下の方に検索ジャンルに沿ったワードを表示する
- 検索項目が選択されていなかったら、ログイン者の検索履歴を表示する

### 投稿の検索（GET /api/search/posts）

- 認証が必要
- 条件（すべて省略できる。指定した条件をすべて満たす投稿を返す。すべて省略した場合は全投稿）
  - `q` … キーワード。題名・投稿説明・タグ名のどれかに含まれていれば一致（部分一致）
    - 大文字小文字・全角半角の違いは区別しない。入力全体を1つの語句として扱う（空白で区切った単語ごとには探さない）
    - 前後の空白を除いて 100 文字まで。超えたら 400
  - `categoryId` … ファッションの種類（マスタの id）。存在しない id は 400
  - `ageGroup` … 投稿者のプロフィールの年代（`EARLY_20S` など）。年代を設定していない投稿者の投稿は出ない。不正な値は 400
- 並び順：いいね数の多い順 → 新しい順 → ID の大きい順（ホームの「おすすめ」と同じ）
  - `design/Searchresults.png` がいいね数の多い順に並んでいるため。関連度順は計算が重くなるため採用しない
- 結果はホームの一覧と同じ形で、ページで区切る（`page`・`size`）。条件に一致した件数（`totalCount`）も返す（「検索結果 〇件」）
- キーワードを指定した場合は検索履歴に記録する（一致する投稿がなくても記録する。記録に失敗しても検索結果は返す）

### ユーザーの検索（GET /api/search/users）

- 認証が必要
- `q` … キーワード。ユーザー名・表示名の部分一致（省略すると自分以外の全ユーザー）
  - フォロー一覧の検索と同じ正規化・エスケープ（前後の空白を除いて小文字にそろえる。`%` `_` は文字として扱う）
  - 全角英数字は半角にそろえない（フォロー一覧の検索と同じ）。100 文字を超えたら 400
- 自分自身は結果に含めない
- 並び順：ユーザー名か表示名の完全一致 → 前方一致 → 部分一致 → ユーザー名の順
- 1件の項目：ユーザー名・表示名（未設定ならユーザー名）・プロフィール画像・身長・性別・自分がフォロー済みか。メールアドレスなどは返さない
- ページで区切る（`page`・`size`）。条件に一致した件数（`totalCount`）も返す
- キーワードを指定した場合は検索履歴に記録する（投稿の検索と同じ履歴）

### 候補ワード（GET /api/search/suggestions）

- 認証が必要
- 検索項目が選ばれたときに出す。最大 10 件
- `categoryId` を指定すると、そのファッションの種類の投稿でよく使われているタグを、使われた投稿数の多い順に返す
  - 省略すると全投稿で数える。非表示にしたタグは出さない。存在しない ID は 400
- 投稿が少なく 10 件に満たない場合は、公式タグ（表示順）で補う（投稿が1件もなくても空にならない）
  - 1件ごとに、よく使われているタグ（`POPULAR`）か、補った公式タグ（`OFFICIAL`）かを返す

### 検索履歴

- ユーザーごとに DB に保存する（テーブル `search_histories`）
- キーワードを入力した検索だけを記録する。キーワードなしで条件だけを指定した検索は記録しない
- キーワードは前後の空白を除き、全角英数字を半角・半角カナを全角にそろえて保存する（100文字まで）
- 同じキーワードで再度検索したら、新しい行は作らずに検索日時を更新する（履歴に同じ語が何度も並ばないようにするため）
  - 大文字小文字の違いは同じ語として扱う（「Y2K」と「y2k」）。表示は最後に入力した形にする
- 1ユーザーあたり 20 件まで保存する。超えた分は検索日時の古いものから削除する
  - 検索欄の下に表示する履歴として、スマホで2〜3画面分あれば足りるため
- 新しい順に表示する（GET /api/search/history）
- 本人が1件ずつ（DELETE /api/search/history/{id}）、またはすべて（DELETE /api/search/history）削除できる
  - 他人の履歴は取得も削除もできない。他人の履歴・存在しない ID を指定しても 204 を返す（他人の履歴の有無が分からないようにするため。連打しても失敗にしないため）
