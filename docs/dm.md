## 仕様

### DM一覧

- 上部に「メッセージリクエスト」への導線を設置し、件数を表示する
- 上部の検索欄からユーザの検索が行える
- やり取り中のユーザは、上からやり取りを最後に行った順に並べる
- 未読のメッセージ数がメッセージ一覧の一番右側に表示される
- 各行に表示する内容
  - ユーザ名
  - 経過時間（例：3分前、1時間前、昨日、2日前、5日前、2週間前）
  - 最新メッセージの本文（省略表示）
  - 状態ラベル（「終了」など）
- 下の「送信したリクエスト」から、自分が申請したリクエストの一覧が表示される

### チャット画面

- 画面上部に相手のユーザ名とアイコンを表示する
- メッセージを入力して送信できる
- ＋ボタンから画像の送信が行える
- 各メッセージに送信時刻を表示する
- 右上のハンバーガーメニューから以下が行える
  - 通報
  - ブロック
  - 会話終了

### 追加機能

- メッセージのピン留め機能
- 通知オフ機能
- 一か月連絡を取っていなかったら自動的に会話終了

### 相談の申し込み

- 相手のプロフィールの「相談する」ボタンから申し込む
- 押すと「申請済み」に変わる（`profile.md` 参照）
- 相談が届くと、相手に通知が飛ぶ（`notification.md` 参照）
- 「相談を申し込む」を押すと、相手にリクエスト（メッセージリクエスト）が送られる。相手が承認して初めて会話できる
- 申し込むときに一言メッセージを添えられる。添えたメッセージは、会話の最初のメッセージとして保存する
- 同じ2人の間で「申請中」または「進行中」の会話は1つまで

### 拒否と再申請

- 拒否された場合、同じ相手には24時間申請を送れない
- 再申請は新しい会話レコードを作る。拒否された会話のレコードは残す（拒否の履歴として扱う）

### 会話の状態

会話は1つのテーブルで管理し、状態で区別する。

| 状態 | 意味 | この状態になる条件 |
| --- | --- | --- |
| 申請中 | 相手の承認待ち | 相談を申し込んだとき |
| 進行中 | 会話できる | 申請中の会話を相手が承認したとき |
| 拒否 | 申請が断られた | 申請中の会話を相手が拒否したとき |
| 終了 | 会話が終わった | ハンバーガーメニューの「会話終了」、または一か月連絡がなかったとき（上記「チャット画面」「追加機能」参照） |

### 相談を受けられる件数の上限

- 相談を受けている「進行中」の会話は、1人あたり3件まで
  - 自分から申し込んだ会話は数えない
  - 申請中の会話は数えない。承認した時点で1件として数える
- 上限の件数は設定ファイルで変更できるようにする
- 上限に達している相手には「現在、新しい相談を受け付けていません」と表示する

### 実装での扱い（`conversations` / `messages` テーブル）

- 相談の申込は `POST /api/conversations`、申し込めるかの確認は `GET /api/users/{id}/consultation-status`
- 申し込めない理由（`reason`）は次のとおり。複数に当てはまる場合は上のものを返す

| reason | 条件 |
| --- | --- |
| `SELF` | 自分自身に申し込んだ（400） |
| `ALREADY_REQUESTED` | 自分の申請が申請中（409） |
| `REQUEST_RECEIVED` | 相手からの申請が申請中（409） |
| `IN_PROGRESS` | 進行中の会話がある（409） |
| `REJECTED_RECENTLY` | 自分の申請が拒否されてから24時間以内（409）。再度申し込める日時を `availableAt` で返す |
| `LIMIT_REACHED` | 相手が受けている進行中の会話が上限に達している（409） |

- 24時間の制限は、拒否された申請を出した本人だけにかける（断った側から申し込むことは止めない）
- 一言メッセージは任意（1000文字まで）。空白だけの場合は保存しない
- 上限の件数は `app.dm.max-received-active-conversations`（環境変数 `DM_MAX_RECEIVED_ACTIVE_CONVERSATIONS`、既定は3）
- 申請中は上限に数えないため、承認の時点でもう一度上限を確認する

#### 承認・拒否・終了

- 承認は `POST /api/conversations/{id}/accept`、拒否は `.../reject`、終了は `.../end`
- 承認・拒否は申し込まれた側だけ、終了は当事者のどちらでもできる
- 拒否・終了から先へは進めない（再申請は新しい会話になる）
- 終了したときは、終了日時と同時に終了した人（`ended_by_id`）を記録する（通知で「誰が終了したか」を使う想定）。一か月連絡がない会話の自動終了では NULL にする

| HTTP | reason | 条件 |
| --- | --- | --- |
| 404 | なし | 会話が存在しない、または当事者でない（会話の有無が分からないよう、どちらも同じ応答） |
| 403 | `NOT_RECIPIENT` | 申し込んだ本人が承認・拒否しようとした |
| 409 | `INVALID_STATUS` | 状態が合わない（終了した会話を承認するなど） |
| 409 | `LIMIT_REACHED` | 承認する時点で、自分が受けている進行中の会話が上限に達している |

#### メッセージ・DM一覧

- 送信は `POST /api/conversations/{id}/messages`（multipart/form-data。`body` と `image` のどちらか一方は必須）。進行中の会話だけ送れる
- 取得は `GET /api/conversations/{id}/messages`。古い順で、最初は最新の30件を返す。さらに古いものは `before`（先頭のメッセージの ID）を付けて読む
  - チャット画面は最新から表示し、上にスクロールして過去を読むため、ページ番号ではなく ID で区切る
- 取得したときに、相手から届いた未読メッセージをすべて既読にする（取得した範囲に関係なく）
- 当事者なら、終了・拒否した会話のメッセージも読める
- DM一覧は `GET /api/conversations`。最終メッセージの新しい順（メッセージがない会話は申込日時）
  - `status` で `requested`（申請中）・`active`（進行中）・`ended`（終了）に絞り込める。指定しなければ3つすべて
  - 拒否された会話は一覧に出さない
  - `requestedByMe` で「メッセージリクエスト」（届いた申請）と「送信したリクエスト」を分けられる
- 会話・メッセージの操作は、当事者でなければ会話が存在しない場合と同じ 404 にする

#### 「相談を申し込む」ボタン（相手のプロフィール・フォロー中一覧）

| 状態 | ボタン |
| --- | --- |
| 申し込める | 押すと一言メッセージ（任意）の入力ダイアログを出す。申し込んだら「送信したリクエスト」（`/dm/sent`）へ移る |
| 申請済み（`ALREADY_REQUESTED`） | 「申請済み」と表示し、押せない |
| 上限に達している（`LIMIT_REACHED`） | 押せない。「現在、新しい相談を受け付けていません。」と表示する |
| 拒否から24時間以内（`REJECTED_RECENTLY`） | 押せない。理由を表示する |
| 相談中（`IN_PROGRESS`） | 「相談中」と表示し、押すとチャット画面へ移る |
| 相手から届いている（`REQUEST_RECEIVED`） | 「リクエストあり」と表示し、押すとメッセージリクエストの画面へ移る |

- プロフィールは `GET /api/users/{id}/consultation-status` で1人分を読む
- フォロー中一覧は、1人ずつ読むと人数分の通信になるため、`GET /api/users/consultation-statuses?ids=1,2,3`（最大50人）でページごとにまとめて読む。判定は1人分の API と同じ
- 申込が 409 で失敗したら（すでに申し込んでいた・上限に達したなど）、エラーを表示して状態を取り直す

#### 画面（`/dm`・`/dm/requests`・`/dm/sent`）

- DM一覧（`/dm`）には、やり取り中の会話（進行中・終了）だけを出す（`status=chats`）。検索欄は相手のユーザー名・表示名の部分一致（`q`）
- 申請中の会話は、受け取ったものを「メッセージリクエスト」（`/dm/requests`、`status=received`）、送ったものを「送信したリクエスト」（`/dm/sent`、`status=sent`）に出す
- 承認・拒否のボタンは、押した時点でその行の両方を無効にする（同じ申請に2回送ると2回目が 409 になるため）
  - 上限に達しているなど、やり直せる失敗のときだけ押せる状態に戻す
- チャット画面（`/dm/{id}`）の上部の相手は `GET /api/conversations/{id}` で読む
- 経過時間は、1日前を「昨日」と表示する
- 件数は `GET /api/conversations/summary` で読む（やり取り中の未読メッセージ・受け取った申請・送った申請）

#### チャット画面（`/dm/{id}`）

- 画面を開いたときは、最新のメッセージが見える一番下を表示する。上端までスクロールすると、さらに古いメッセージを読む
- 新しいメッセージが届いたときは、一番下付近を見ているとき（または自分が送ったとき）だけ一番下までスクロールする
- 送信時刻は、今日なら「14:02」、それより前なら「10/4 14:02」と表示する
- ＋で画像を選ぶと入力欄の上にプレビューし、送信ボタンで本文と一緒に送る（選んだ時点では送らない）
- 右上のメニューは「会話を終了する」だけ（通報・ブロックは未実装）。取り消せないため、確認ダイアログを出す
- 送れるのは進行中の会話だけ。申請中・終了・拒否では入力欄の代わりに理由を表示する

新しいメッセージの取得

- リアルタイムに届く仕組みがまだないため、画面を開いている間は5秒ごとに、最後のメッセージより新しいもの（`after`）と会話の状態を取り直す
- タブが裏にある間は止め、戻ってきたらすぐに取り直す
- 終了・拒否した会話は新しいメッセージが来ないため、取り直さない
- 取り直すたびに相手のメッセージは既読になる（開いている間は読んでいるものとする）
- 通知の仕組み（WebSocket など）ができたら、5秒ごとの取り直しを置き換える

#### 下部ナビの DM のバッジ

- やり取り中の会話の未読メッセージ数と、受け取った申請の件数の合計を出す
- リアルタイムに届く仕組みがまだないため、次のタイミングで取り直す（遅れても最大1分）
  - 下部ナビのある画面を開いたとき・画面を移動したとき
  - ブラウザのタブに戻ってきたとき
  - 画面を開いている間は60秒ごと（タブが裏にある間は取り直さない）
  - 承認・拒否の直後
- 通知の仕組み（WebSocket など）ができたら、60秒ごとの取り直しを置き換える

- 通報の送信先と、その後の処理

- 既読表示の有無
- 拒否された申請を、申し込んだ側にどう見せるか
  - 現在は DM一覧に出さないため、拒否されたのか未対応なのかが分からない
